## Why v3.2 exists

Wave 3 produced guide traffic without attributed registrations. The predeclared H1 in `WAVE_3_ONBOARDING_HYPOTHESIS_2026-10-11.md` identified a deterministic contract ambiguity: `POST /api/peers` requires `Content-Type: application/json`, while Peer Guide v3.1 did not explicitly include that required header in its three-step quick-start.

v3.2 keeps the same auth model, endpoints and three-request flow, but adds explicit JSON headers, expected HTTP 200/201 statuses, HTTP 415 troubleshooting, a raw reference-client URL, and aggregate `peer-registration-attempt` / `peer-registration-rejected` counters using the existing referral table.

No D1 schema migration, raw-IP logging, message-body logging, bearer-token logging, auth weakening or trust/evidence elevation was introduced.
